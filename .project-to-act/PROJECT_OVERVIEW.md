## 项目目标

- 在已有智慧食堂业务内核上，落地一个面向员工/学生、食堂运营人员、食堂管理者的统一助手入口。
- 首个可验证目标：用户身份与食堂范围能够进入 Agent Runtime，助手能够按角色加载不同上下文，并保留现有确定性业务 Tool/Run 执行路径。
- 学习环境允许使用并持久化仓库中的初始化数据集作为业务事实，便于演示菜单、库存、采购和溯源闭环。

## 范围

### 包含

- 角色上下文：员工/学生、食堂运营人员、食堂管理者。
- AgentScope Java 2.x HarnessAgent 适配边界、会话上下文和模型可选接入。
- 菜单、库存、采购、食品溯源等现有业务服务与 Agent Runtime 的连接。
- 员工/学生端已发布菜单查询、个人未支付消费订单查询/创建/取消，以及对应的确认式助手 Tool。
- 员工/学生端一单一评价和个人投诉提交/查询，以及对应的确认式助手 Tool（SC-010 已完成）。
- 员工/学生端个人消费订单学习环境模拟支付，以及对应的确认式助手 Tool（SC-011 已完成）。
- 可复现的学习数据和最小纵向切片测试。

### 非目标

- 本阶段不接真实 POS、真实支付网关、门禁、人脸识别或生产供应商系统。
- 本轮实现员工/学生评价与投诉提交/个人查询，以及订单 `STUDY_MOCK` 模拟支付；暂不实现退款、余额扣款、真实订单金额结算、投诉管理端受理回复和库存扣减。
- 本阶段不实现完整预测算法、RAG 知识库、MCP 集群或 Multi-Agent 编排。
- 不把 LLM 作为库存、BOM、金额和采购数量的事实来源。

## 技术路线与关键约束

- Java 17、Spring Boot、MySQL/H2、AgentScope Java 2.x、React/Vue、SSE。
- AgentScope 作为 Agent Runtime/Harness 能力；业务事实仍由现有应用服务、数据库和 Tool 承载。
- 默认先保持确定性规则和现有模型适配，AgentScope 模型通道通过配置启用。

## 数据与安全边界

- 敏感信息处理：只记录脱敏摘要、证据 ID 和受控位置，不粘贴原始敏感数据。
