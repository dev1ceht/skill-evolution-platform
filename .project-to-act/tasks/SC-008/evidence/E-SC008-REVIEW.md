# E-SC008-REVIEW

## 复审基线

- 固定点：`8325fa1`（SC-007 完成提交）
- SC-008 实现提交：`1dd4de2`；解析与测试加固提交：`d5bf003`
- 复审方式：Standards / Spec 双轴审查，检查完整差异、需求契约和既有 Java/Spring 测试约定。

## 发现与处理

首轮审查发现测试使用固定日期配合“明天”，以及解析器可能把查看/否定 Draft 的语句误判为写入；同时补充了权限、幂等 payload 冲突和缺少日期澄清证据。后续复审又发现文档中的裸写法 `采购 Draft 2026-08-22`、非法 ISO 日期预览和澄清续答证据缺口。以上均已在 `d5bf003` 前后通过实现与测试修正：

- Draft 识别要求明确生成/创建，或带有效日期的裸 Draft；查看、查询、否定、取消不会写入。
- ISO 日期在预览前解析校验，非法日期直接澄清。
- `procurement.plan.generate` 纳入持久化澄清意图白名单，并增加续答 HTTP 测试。
- 最终 Standards 复审无 P0/P1；仅提出测试日期断言的 P2 判断，已改为单次捕获 `expectedTomorrow`。
- 最终 Spec 复审无 P0/P1/P2，确认 `WAITING_CONFIRMATION`、确定性 DRAFT、权限/范围、幂等和无订单/无预测边界均满足。

## 结论

SC-008 在个人学习环境条件下通过。没有新增生产化承诺；真实预测服务、采购提交和供应商系统接入作为后续独立范围。
