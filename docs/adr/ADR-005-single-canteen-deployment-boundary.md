# ADR-005: 固定单食堂运行边界

## 状态

已接受

## 背景

当前项目的业务页面、采购、库存和食品安全闭环只面向一个实际食堂使用。旧代码为了兼容早期平台化设计，在请求、权限和持久化中携带学校与食堂范围参数，页面也存在展示范围标识的可能。

## 决策

- 生产部署通过 `SingleCanteenContext` 固定唯一业务食堂，默认标识为 `SCHOOL-001 / CANTEEN-001`，可由部署配置覆盖。
- 页面不提供学校/食堂切换；前端路由和业务请求只操作当前固定食堂。
- 后端收到不同范围参数时直接拒绝，不能通过修改查询参数访问另一食堂。
- 旧数据库范围列暂作为兼容存储字段保留，业务代码不再把它们当作可选择的业务上下文；后续在确认所有旧关联移除后再物理删列。
- 测试环境可以关闭固定范围校验，以保留跨范围隔离测试的覆盖面。

## 后果

- 单食堂页面和业务服务更简单，不需要范围选择器、跨学校汇总和供应商门户。
- 旧接口暂时仍可接收范围参数，避免一次性重写所有持久化适配器，但生产值只允许固定范围。
- 若将来重新支持多食堂，需要重新评估权限、路由、数据迁移和汇总模型，不能只打开配置开关。
