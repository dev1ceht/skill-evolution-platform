# 智慧食堂架构

```text
运营人员 / Agent
       |
       v
Vue 页面与业务状态
       |
       v
Spring Boot REST API
       |
       +--> 菜单 / 采购 / 库存 / 台账 / 预警 / 溯源领域服务
       |             |
       |             +--> 事务、范围授权、幂等与审计
       |             +--> Jdbc Adapter --> MySQL
       |
       +--> 规范化外部 Adapter 端口
                     |
                     +--> 区县平台 / 明厨亮灶 / 晨检设备 / 通知渠道

Business Skills + SOP Manifest
       |
       +--> 菜单、采购、库存、台账、食品安全、溯源业务操作
       +--> 跨业务组合、前置校验、状态迁移、运行证据
```

`skills/canteen-*` 是面向运营人员的业务操作入口：可以解析业务文件、执行计算、生成订单/批次/台账/溯源结果，并在需要时请求确认。`smart-canteen-sop` 是跨业务编排边界，不是数据库访问层；所有真实状态写入仍必须经过后端服务的授权、事务和幂等控制。

OpenAPI 契约位于 `contracts/`，作为后端业务 Skill 调用端口的输入依据。契约解析和客户端生成属于项目辅助工具，不再作为可触发的 Skill 暴露给运营人员。

外部平台和设备只通过端口接入。端口实现必须完成认证、范围映射、来源唯一性、超时、重试和错误规范化；缺少真实合同或凭据时保持 `port-only`。
